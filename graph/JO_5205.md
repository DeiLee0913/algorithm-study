# 5205. 장난감조립

- **출처 / 링크:** [정올 5205 — 장난감조립](https://jungol.co.kr/problem/5205) (백준 [2637](https://www.acmicpc.net/problem/2637)과 동일)
- **난이도·태그:** 골드 2 — 그래프, 위상 정렬
- **상태:** AC (AI 도움)
- **메인 아이디어(폴더):** graph
- **보조 태그:** topological-sort, Kahn, DAG, DP-on-DAG
- **풀이 위치:** `graph/JO_5205.java`

### 잘한 점

- 부품 관계를 **방향 그래프(X → Y, K)** 로 두고, 완제품 `n`에서 아래로 필요 개수를 전파하는 골격까지는 잡을 수 있었다.

### 왜 어려웠는지 / 막힌 지점

- **위상 정렬**이 메인인지 처음에 바로 못 잡았다. 예제처럼 번호가 작은 쪽(기본) → 중간 → 완제품(`n`) 순으로 보이는 것에 끌려, **부품 번호 자체가 이미 조립 순서를 보장한다**고 착각했다. 그래서 “번호 작은 것부터 / 큰 것부터 돌리면 되지 않나?”로 흐르기 쉽고, **번호와 무관한 선행 관계가 있는 DAG**라서 위상 정렬로 순서를 강제해야 한다는 감각이 늦었다.
- 마찬가지로 부품 번호 자체가 조립 순서를 보장한다고 착각해서 **기본 부품 vs 중간/완제품**을 가르는 표시를 따로 둘 생각을 못했다. 입력에서 `X`로 한 번이라도 나온 부품은 조립에 쓰이는 쪽(`isMiddle[X] = true`)이고, 한 번도 `X`가 아닌 부품만 기본 부품이다. 이 플래그 없이 출력 조건을 만들려다 헤맸다.
- 진입 차수(`degrees` / `inDegree`)로 “나를 필요로 하는 상위 부품을 모두 처리한 뒤에야” 큐에 넣는 흐름, 그리고 `needed[next] += needed[cur] * weight`로 **개수를 곱해 누적**하는 식을 AI 도움으로 정리했다.

### 최종 풀이 요약

- 간선: `X Y K` → `X`를 만들 때 `Y`가 `K`개 필요 → `edges[X] → (Y, K)`, `degrees[Y]++`, `isMiddle[X] = true`.
- `needed[n] = 1`로 완제품 1개를 고정한 뒤, **진입 차수 0**인 정점부터 Kahn 위상 정렬.
- 큐에서 `cur`을 꺼낼 때마다 이웃 `next`에 `needed[next] += needed[cur] * weight`, `degrees[next]--`, 0이 되면 큐에 추가.
- 출력: `!isMiddle[i]`인 `i`(기본 부품)에 대해 `i`와 `needed[i]`를 번호 오름차순으로 출력.

### 새로 알게 된 것 / 다음에 쓸 것

- **조립·레시피·선수과목**처럼 “A가 끝나야 B”가 보이면 먼저 **DAG + 위상 정렬**을 의심한다. 예제 번호가 예뻐 보여도 **정점 번호 ≠ 위상 순서**로 둔다.
- 출력 대상이 “리프/기본 단위”일 때는, 그래프 탐색만이 아니라 **입력에 등장한 역할로 표시 배열**(`isMiddle` 등)을 두는 습관을 들인다.
- 필요 개수는 위상 순서 위에서 **부모 필요량 × 간선 가중치**로 전파하는 DAG DP와 같다.

### 참고한 것

- 처음 헤맬 때 **AI** 도움으로 위상 정렬·`isMiddle`·개수 누적 식을 정리함.
