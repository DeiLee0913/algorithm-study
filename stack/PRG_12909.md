# 12909. 올바른 괄호

- **출처 / 링크:** [프로그래머스 12909](https://school.programmers.co.kr/learn/courses/30/lessons/12909)
- **난이도·태그:** Level 2 — 스택, 괄호
- **상태:** AC
- **메인 아이디어(폴더):** stack
- **보조 태그:** balance, 조기 종료
- **풀이 위치:** `stack/PRG_12909.java`

### 잘한 점

- 닫는 괄호가 나왔을 때 스택이 비어 있으면 즉시 올바르지 않다고 판단했다.
- 순회가 끝난 뒤 남은 여는 괄호도 확인해 길이와 방향이 모두 맞아야 한다는 조건을 처리했다.

### 왜 어려웠는지 / 막힌 지점

- `c == ')' && st.isEmpty()`를 별도의 예외 조항처럼 봐야 하는지 고민했다.
- 하지만 이 조건은 임의의 일회성 예외가 아니다. 문자열의 어떤 접두사에서도 닫는 괄호 수가 여는 괄호 수보다 많아지면 안 된다는 불변식을 검사한다.
- 현재의 `st.peek() != c` 방식은 입력 문자가 `(`와 `)`뿐이라는 사실에 기대어 동작한다. 의도인 “여는 괄호를 닫는다”가 코드에 직접 드러나지 않아 규칙이 단편적으로 보일 수 있다.

### 최종 풀이 요약

현재 코드는 한 번의 순회로 괄호를 처리하므로 시간 복잡도는 `O(n)`이다. 다만 괄호의 종류가 하나뿐이므로 실제로 필요한 정보는 스택 전체가 아니라 현재 열려 있는 괄호의 개수다.

보다 일관적인 규칙은 다음과 같다.

```java
balance += c == '(' ? 1 : -1;
if (balance < 0) return false;
```

순회가 끝난 뒤 `balance == 0`인지 확인하면 된다. 이 방식은 시간 `O(n)`, 추가 공간 `O(1)`이며, 닫는 괄호가 너무 일찍 나온 경우도 “잔액이 음수가 되는 순간 실패”라는 같은 규칙으로 처리한다.

### 새로 알게 된 것 / 다음에 쓸 것

- 조기 종료 자체는 비효율적인 예외 처리가 아니라, 접두사 불변식이 깨지는 즉시 중단하는 효율적인 구현이다.
- 중요한 것은 예외를 없애는 것이 아니라, 그 조건을 문제의 불변식으로 설명할 수 있는지다.
- 스택 풀이를 유지한다면 `(`일 때 push, `)`일 때 비었는지 확인 후 pop처럼 의도를 직접 표현하고, 괄호 종류가 하나뿐이면 balance 카운터를 우선 고려한다.
