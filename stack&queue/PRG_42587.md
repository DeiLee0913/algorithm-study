# 42587. 프로세스

- **출처 / 링크:** [프로그래머스 42587 — 프로세스](https://school.programmers.co.kr/learn/courses/30/lessons/42587)
- **난이도·태그:** Lv.2 — 스택/큐
- **상태:** AC
- **메인 아이디어(폴더):** stack&queue
- **보조 태그:** queue, priority-queue, simulation
- **풀이 위치:** `stack&queue/PRG_42587.java`

### 잘한 점

- 처음 틀린 뒤, “대기열에서 우선순위가 더 높으면 다시 큐에 넣기” 규칙을 반영해 접근을 고친 뒤부터는 거의 스스로 풀었다.

### 왜 어려웠는지 / 막힌 지점

- 지문 중 **“큐에 대기중인 프로세스 중 우선순위가 더 높은 프로세스가 있다면 방금 꺼낸 프로세스를 다시 큐에 넣습니다.”** 를 처음에 대충 읽어서 접근법을 잘못 잡았다.
- 그 때문에 `PriorityQueue` 하나만으로 처리하려다 틀렸고, 그 부분에서 잠깐 헤맸다.

### 최종 풀이 요약

- 대기 순서를 지키는 **일반 큐** `(index, priority)` + 현재 남은 최댓값용 **최대 힙**을 같이 쓴다.
- 큐에서 하나 꺼낸 뒤, 그 우선순위가 힙의 현재 최댓값과 같으면 실행(순서 `cnt++`). `location`이면 종료.
- 아니면 다시 큐 뒤로 보낸다. 실행할 때마다 힙에서도 해당 우선순위를 꺼내 다음 최댓값을 갱신한다.

### 새로 알게 된 것 / 다음에 쓸 것

- 이 문제는 “우선순위만 높은 순”이 아니라 **큐 순서 + 재삽입** 시뮬레이션이다. PQ만으로는 대기열 규칙이 안 맞는다.
- Java `PriorityQueue` 기본은 오름차순이라, 최댓값이 필요하면 `Comparator.reverseOrder()`로 최대 힙을 만든다.

### 참고한 것

- `PriorityQueue` 선언 시 `reverseOrder` 처리 — **AI** 힌트. 그 외 접근·구현은 대체로 스스로 정리.
